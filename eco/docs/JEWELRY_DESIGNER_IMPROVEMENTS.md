# מדריך שיפורים – מעצבת התכשיטים

סקירה של המעצבת (`/customjewelry`), רשימת התקלות שנמצאו, ומה תוקן.

> **✅ סטטוס: כל הסעיפים במסמך תוקנו בקוד.**
> מה שנשאר לעשות ידנית מרוכז בסוף המסמך תחת
> [מה עדיין דורש פעולה ממך](#מה-עדיין-דורש-פעולה-ממך) — בעיקר ביטול הטוקנים שנחשפו
> ועדכון משתני הסביבה ב-Vercel. בלי זה, סעיפים 2 ו-3 לא באמת סגורים.

> **מה נבדק ומה לא:** הבנייה עוברת נקי, וכל הדפים נטענים (200) בשרת פיתוח מקומי.
> לא ניתן היה להריץ זרימת עיצוב מלאה מקצה לקצה כי ה-Strapi
> (`strapi-7iq2.onrender.com`) לא הגיב בזמן הבדיקה — כנראה instance כבוי ב-Render.
> כדאי לעבור עיצוב אחד שלם אחרי שהוא חוזר לאוויר.

## 🔴 קריטי – אבטחה ותקינות

### 1. כתובת ה-Strapi ברירת המחדל הייתה `localhost`

```ts
// לפני — src/lib/api/strapiClient.ts, src/routes/api/jewelry-order/+server.ts
const STRAPI_URL = import.meta.env.VITE_STRAPI_URL || 'http://localhost:1337';
```

כל שאר האתר פנה ישירות ל-`https://strapi-7iq2.onrender.com`, ורק שני הקבצים האלה
נפלו ל-localhost. אם `VITE_STRAPI_URL` לא היה מוגדר ב-Vercel — גלריית התבניות נפלה
עם "לא נמצאו תבניות זמינות כרגע" וההזמנות נכשלו, בזמן שכל שאר האתר עבד. נקודת כשל
שקטה שקשה לאבחן.

**תוקן:** מקור אמת אחד ב-`src/lib/config/strapi.ts`, עם ברירת מחדל לפרודקשן.

### 2. טוקן טלגרם נשלח לדפדפן של כל מבקרת

`import.meta.env.VITE_*` נדחס על ידי Vite לתוך ה-bundle של **הדפדפן**. כל משתנה עם
תחילית `VITE_` הוא ציבורי בהגדרה, והקוד השתמש בטוקן הבוט בצד הלקוח:

```js
// לפני — src/routes/sadnaot/+page.svelte
const Token = import.meta.env.VITE_TELEGRAM_BOT_TOKEN;
const url = `https://api.telegram.org/bot${Token}/sendMessage?...`;
```

אימות: בבנייה, `api.telegram.org/bot...` הופיע בקבצי הלקוח
(`_app/immutable/nodes/*.js`). מי שקוראת את הטוקן יכולה לשלוח הודעות בשם הבוט,
לקרוא את העדכונים שלו ולעשות לו DoS.

**תוקן:**
- endpoint חדש `src/routes/api/contact/+server.ts` — הדפים שולחים אליו, הוא שולח לטלגרם.
- `src/lib/server/telegram.ts` — קורא את הקרדנציאלס מ-`$env/dynamic/private`.
- `sadnaot` ו-`sadna` עברו לקרוא ל-`/api/contact`.
- `api/teleg` ו-`api/jewelry-order` עברו למודול המשותף.

### 3. טוקן Strapi עם הרשאות כתיבה שמור בריפו

```js
// לפני — scripts/sync_components.js:7, scripts/sync-strapi-template.js:14
const STRAPI_API_TOKEN = "0392108fd94a9cd10bae241624798ad4...";
```

**תוקן:** נקרא מ-`process.env.STRAPI_API_TOKEN` (מה שההודעה בסקריפט כבר הניחה).
הטוקן עדיין בהיסטוריית git — **חייבים לבטל אותו**, ראי בסוף המסמך.

בנוסף, `strapiClient.ts` הכיל קוד כתיבה מת (`ordersApi`, `uploadFile`,
`checkStrapiConnection`) שביצע כתיבות ישירות מהדפדפן. הוסר — כל הכתיבות עוברות דרך
השרת עם טוקן פרטי (`src/lib/server/strapi.ts`).

## 🟠 באגים פונקציונליים

### 4. חישוב מידת הצמיד — מרווח התפס התווסף במקום להיגרע

```ts
// לפני — braceletCalculations.ts
const claspSpace = 1.5;                                   // "space reserved for clasp"
const availableBeadSpace = wristCircumference + claspSpace; // אבל נוסף, לא נגרע
const recommendedBeadCount = Math.floor(maxBeadCount * 0.9);
```

ההערה אמרה "מקום שמור לתפס", אבל בפועל המרווח **נוסף** למקום הפנוי לחרוזים. במקביל,
`DesignCanvas` חישב את אותו דבר בנוסחה אחרת (`wrist - CLASP`) ועם קוטר חרוז אחר
(0.7 מול 0.5) — כלומר מספר הנקודות שצוירו על הבד לא תאם למספר שהוולידציה חשבה.

**תוקן** עם מודל פיזי מפורש:

```ts
totalCircumference  = היקף פרק היד + מרווח נוחות
availableBeadSpace  = totalCircumference − אורך התפס
```

בלי מקדם 0.9 נוסף — מרווח הנוחות הוא מה שעושה את ההתאמה, ושניהם יחד קיצרו את המחרוזת
יותר מדי. הקבועים יושבים עכשיו ב-`BRACELET_GEOMETRY` אחד, וגם הקנבס משתמש בהם.

תוצאה (תפס 1.5 ס"מ, מרווח 1.0 ס"מ):

| פרק יד | חרוז | חרוזים | היקף גמור | מרווח בפועל |
|---|---|---|---|---|
| 14 ס"מ | 0.7 | 19 | 14.8 ס"מ | +0.8 |
| 17 ס"מ | 0.7 | 23 | 17.6 ס"מ | +0.6 |
| 17 ס"מ | 1.2 | 13 | 17.1 ס"מ | +0.1 |
| 20 ס"מ | 0.7 | 27 | 20.4 ס"מ | +0.4 |

### 5. קוטר חרוז קבוע 0.5 ס"מ בכל החישובים

הקטלוג כולל חרוזים של 0.5 / 0.8 / 1.2 ס"מ, וחרוזי אותיות של 0.8 — אבל הסטור העביר
תמיד `0.5`. בנוסף, `currentBraceletCalculation` חישב ממוצע על פני **כל הקטלוג**
תחת שם מטעה (`selectedBeads`), במקום על החרוזים שהלקוחה בחרה.

**תוקן:** `beadDiameter()` / `averageBeadDiameter()` משותפים, והחישוב מבוסס על
החרוזים שהונחו בפועל.

### 6. מחיקת טקסט אישי השאירה חרוזי אותיות בהזמנה

```ts
// לפני — הבאג חזר בשני מקומות ב-createLetterBeadsFromText
newSelectedComponents.delete(positionId);            // נמחק מהמפה
...
const component = newSelectedComponents.get(comp.positionId);  // undefined — כבר נמחק
return !isLetterBead;                                // תמיד true → הרשומה נשארה
```

הסינון חיפש את הרכיב במפה **אחרי** שהוא נמחק ממנה. התוצאה: לקוחה שכתבה שם, מחקה
אותו והזמינה — התכשיט על המסך והמחיר לא כללו את האותיות, אבל
`designConfiguration` שנשלח בהזמנה כן.

**תוקן:** המיקומים נאספים ל-`Set` לפני המחיקה, והסינון עובד מולו.

### 7. הודעות שגיאה באנגלית הוצגו ללקוחה

`"Adding this bead would exceed capacity by 1.3cm"` ודומותיה הגיעו ישירות למסך.
**תוקן:** 16 הודעות תורגמו לעברית.

### 8. חרוז-אות בתליון המרכזי — פיצ'ר שלא עבד

`ComponentSelector` התיר במפורש חרוז-אות ב-`pendant_center`, ואז שורה אחת אחר כך
פסל אותו כי `selectedType` אותחל ל-`position.type` (= `pendant`).

**תוקן:** פונקציה אחת, `isComponentAllowedAt()`, ו-`selectedType` מתחיל ב-`all`
במיקום המרכזי.

### 9. קוד מת ושבור

`updateWristSizeFromCharms` החזיק `previousCharmAdjustment` כמשתנה מקומי שאופס בכל
קריאה — כלומר היה מנפח את מידת היד בכל פעם. הקריאה היחידה אליו הייתה מנוטרלת בהערה.
**תוקן:** נמחק.

### 10. שחזור עיצוב הסתמך על עותק ישן של התבנית

התבנית כולה (כולל `basePrice` ו-`positions`) נשמרה ונטענה מהדפדפן — לקוחה שחזרה
אחרי שינוי מחיר ב-Strapi הייתה רואה ומזמינה במחיר הישן.

**תוקן:** נשמר `templateId` בלבד, התבנית נטענת מחדש מ-Strapi, ורכיבים שכבר לא קיימים
מוסרים — עם הודעה ללקוחה כמה הוסרו.

### 11. תמונת התצוגה המקדימה שברה את השמירה האוטומטית

`previewImage` (data-URL של PNG ב-scale 2, מאות KB) נשמר ל-localStorage. מרגע
שנוצרה תצוגה מקדימה, הכתיבה חרגה מהמכסה ונכשלה — **בשקט**. הפיצ'ר "העיצוב שלך נשמר"
הפסיק להתקיים בדיוק בשלב הקריטי.

**תוקן:** לא נשמר יותר (הוא נוצר מחדש בשנייה), וכשל שמירה מוצג ללקוחה.

## 🟡 חוויית משתמש

### 12. שגיאת ולידציה קטנה חסמה את כל המסך

אותו overlay שחור שימש גם ל"נפילת רשת" וגם ל"החרוז הזה לא נכנס" — הערה רכה שהייתה
צריכה להופיע ליד החרוז.

**תוקן:** סטור חדש `designerNotice` להודעות inline שנעלמות לבד; `designerError`
נשאר לכשלי רשת/שרת בלבד.

### 13. `100vh` נחתך בדפדפני מובייל

`height: 100vh` + `overflow: hidden` במסך הפתיחה — בטלפון קטן כפתור "התחילי לעצב"
עלול היה להיחתך בלי דרך לגלול אליו.
**תוקן:** `100dvh` + גלילה. נבדק בדפדפן ב-390px — הכפתור נראה במלואו.

### 14. מרקרים בגדלים שונים נראו זהים במובייל

`:global(.design-canvas .position-marker circle) { r: 14 }` תפס **כל** עיגול בקבוצה —
כולל הילת ה-hover וטבעת ה-pulse — כך שההיררכיה small/medium/large נעלמה.
**תוקן:** הגדלים מחושבים ב-JS עם `matchMedia`.

### 15. רכיבים שנבנו ולא חוברו

`TextInputExample.svelte` ו-`BraceletDesignExample.svelte` היו קבצי דמו בלבד — נמחקו.
`index.ts` ייצא גם את `JewelryDesignerPage.svelte` **שמעולם לא היה קיים** — תוקן.

### 16. תמונות נטענו בגודל מלא

הגלריה והסלקטור השתמשו ב-`<img>` פשוט בזמן ש-`OptimizedImage.svelte` נבנה בדיוק לזה
ולא היה בשימוש באף מקום. הסלקטור טוען עד 100 רכיבים בבת אחת.

**תוקן:** `OptimizedImage` בשימוש, עם `resolveMediaUrl()` שמוסיף טרנספורמציות
Cloudinary לפי רוחב (`w_320` לגלריה, `w_96` לסלקטור) וגם הופך נתיבי `/uploads/...`
יחסיים לכתובת Strapi מלאה.

## מה עדיין דורש פעולה ממך

הקוד מוכן. שלושת אלה הם מחוץ לריפו:

### 1. לבטל את הטוקנים שנחשפו (דחוף)

- **טלגרם:** BotFather → `/revoke` → להנפיק חדש.
- **Strapi:** Settings → API Tokens → Revoke לטוקן שהיה בסקריפטים → להנפיק חדש.

הטוקן של Strapi בהיסטוריית git, ולכן מחיקה מהקוד לבדה לא מספיקה.

### 2. לעדכן משתני סביבה ב-Vercel

```
TELEGRAM_BOT_TOKEN=<הטוקן החדש>
TELEGRAM_CHAT_ID=<כמו קודם>
STRAPI_API_TOKEN=<הטוקן החדש>
STRAPI_URL=https://strapi-7iq2.onrender.com
```

הקוד מקבל בינתיים גם את השמות הישנים עם `VITE_`, כדי שכלום לא יישבר באמצע. **אחרי**
שהחדשים עובדים — למחוק את הישנים.

### 3. לאשר את קבועי המידה

`BRACELET_GEOMETRY` ב-`src/lib/utils/braceletCalculations.ts`:

```ts
claspSpace: 1.5,      // אורך התפס בס"מ
easeAllowance: 1.0    // מרווח נוחות מעל היקף פרק היד
```

מספרים סבירים, אבל את מכירה את החומרים — אם התפס אצלך באורך אחר, זה המקום היחיד
לשנות והכל מתעדכן.

**שווה לבדוק:** הזמנות שכבר יצאו חושבו בנוסחה הישנה ויצאו רפויות בערך 2–3 ס"מ.

## דף הנחיתה `/tachshit-ishi`

מסלול שיווקי שמוביל למעצבת. המעצבת עצמה לא שונתה.

- **קובץ:** `src/routes/tachshit-ishi/+page.svelte`
- כל הקריאות לפעולה מפנות ל-`/customjewelry`.
- הקישור "צרי עיצוב משלך" בדף הבית מפנה עכשיו לדף הנחיתה
  (`desctopfront.svelte`, `mobilefront.svelte`). אם תעדיפי שייכנס ישר למעצבת — זו
  שורה אחת בכל אחד.
- נוסף ל-sitemap בעדיפות 0.9.
- SEO: תגיות `Head` + JSON-LD של `Service` ו-`FAQPage` — השאלות והתשובות יכולות
  להופיע ישירות בתוצאות החיפוש.
- כל האיורים (צמיד, חרוזים, אותיות, סרגל מידות) הם SVG inline — אין נכסים חדשים
  לתחזק, והדף נטען מהר גם בסלולר.
- נבדק ללא גלישה אופקית ב-1440px וב-390px; כל האנימציות מכובות תחת
  `prefers-reduced-motion`.

### מה כדאי להוסיף כשיהיה חומר

הסעיף "אותה תבנית, שלוש נשים שונות" מצייר כרגע שלוש אפשרויות ב-SVG. כשיהיו **צילומים
אמיתיים של תכשיטים שיוצרו במעצבת** — כדאי להחליף אותו בגלריית תמונות. זה הדבר היחיד
שמשכנע יותר מאיור.

(התמונות הקיימות ב-`static/photo_*.jpg` הן פוסטרים על "חוטים של אור" ולא צילומי
תכשיטים, ולכן לא נכנסו לדף.)

תוספות אפשריות: המלצות לקוחות, טווח מחירים משוער, וזמן אספקה.
